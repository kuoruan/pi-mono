Add a mode config option (`manual` | `default` | `auto`, default `default`) deciding who adjudicates the model's non-allow verdicts: manual hands every deny and defer to the human (the reviewer becomes an advisor whose deny reason surfaces as a notification), default keeps the shipped behavior (decisive denies final, uncertainty asks), and auto runs fully automatic and fail-closed — the model's own uncertainty is denied with the defer's clarification request carried as the deny reason (so the agent can adapt instead of hitting a silent block), while reviewer machinery failures (timeouts, unparseable replies) still defer to the human escape valve with an explanatory notification. The mode is switchable at runtime via the `/ai-guard` settings menu (two-stage argument completion) and the `ctrl+alt+g` cycle shortcut; session overrides persist into pi's session file (custom entries, never LLM context) and restore on resume, re-deriving on tree navigation. The footer only renders deviations from the `default` baseline. A tripped circuit breaker's forced verdict bypasses the mapping by design: the default forced deny keeps auto sessions uninterrupted, while an explicitly configured forced defer interrupts the human as the reviewer-untrusted escape valve (the config loader warns about that combination).
