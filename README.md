# pi-mono

A monorepo for PI Agent extensions, skills, and other packages, managed with pnpm workspace.

## Structure

```
.
├── extensions/   # PI Agent extension packages
├── skills/       # PI Agent skill packages
├── .changeset/   # Release change records
└── .github/      # CI / Release workflows
```

## Requirements

- Node.js >= 22 (see `.node-version`)
- pnpm 10 (pinned via the `packageManager` field; corepack auto-activates)

## Quick start

```bash
# Install dependencies
pnpm install

# Lint
pnpm lint

# Format
pnpm format

# Add a changeset (record changes before release)
pnpm changeset
```

## Adding a package

Create a new directory under `extensions/` or `skills/` with a `package.json` and it will be picked up by the workspace:

```
extensions/my-extension/
├── package.json
└── src/index.ts
```

Package names should use the `@pi-mono/<name>` scope.

## Release flow

Releases use [Changesets](.changeset/README.md) to manage independent per-package versions:

1. On a feature branch, commit your code along with the change record generated by `pnpm changeset`.
2. After the PR merges to `master`, GitHub Actions automatically opens a **Version Packages** PR.
3. When the Version PR merges, packages are published to npm automatically.

> Configure `NPM_TOKEN` in the repository Secrets.
