# pi-pigment

## 0.4.3

### Patch Changes

- 20434a3: **The generation-time AA policy moved into its own module, and its tiers became data.** Which pi surfaces a token is painted on, and what contrast that pairing must clear, now live in one table in `aa-policy.ts`; the converter hands it the surfaces it resolved and reports what it flags. A slot's rule is readable at a glance instead of emerging from five positional arguments at fifteen call sites, and adding a slot means adding a row — a slot adjusted without one is now a compile error rather than a silent skip of enforcement.

  **The contrast math moved to `core/color.ts`**, the module the glossary already names for color math, so generation and render call the same functions from one seam instead of reaching through the syntax theme. `syntax-theme.ts` is left owning the token theme alone.

  The move changed no generated byte and no diagnostic line. The policy's three tiers, the style zone, the plateau between the endpoints and the unreachable-pairing case now also have rule-level tests of their own, each checked against an independent enumeration of the ramp, so a policy change fails as a broken rule instead of churning golden hex.

- 20434a3: **Generated themes enforce AA by pairing, in three tiers, and never fake it.** Contrast is measured against the surfaces pi actually paints each token on — pi's own binding table, mirrored by name — so a selected row no longer drags code colors that never touch it, and `toolDiff*` no longer answers to the message panels.

  The tiers matter: a 4.5 bar applied to every slot rewrites a theme rather than fitting it. Body text (`text` and the slots carrying its value) clears 4.5 outright — pi gates those at 4.5 itself, so stopping short would only mean a second adjustment at render time. Secondary labels (`muted`, `dim`, the thinking steps, markdown rules) are lifted only to the 3:1 readability floor, and a slot already above it keeps the author's emphasis step, reported as readable but not AA: raising a dim label to 4.5 erases the distinction the dimming was there to express. Below the floor is a defect rather than a style, so it is lifted. Structural borders hold 3:1; `borderMuted`, `scrollbar*` and `mdHr` stay decorative.

  Where no color a terminal can show clears a surface, the source color is kept and the pairing is reported with its ratio — a generated theme is never repainted white or black just to pass a check. Which color does clear is settled along the whole ramp, not only at its two ends: contrast depends on relative luminance alone, so the search works in luminance — it takes the bands the surfaces leave workable and bisects the ramp's monotone luminance to reach a color in one. That is what lifts `github-dark-high-contrast`'s `accent`, `muted`, `success` and `warning`, and `github-light-high-contrast`'s `accent`, `dim` and `muted`, to a color that clears their floor instead of being kept as conflicts. The body text on those two themes' selection rows is what stays reported, because on each theme that row sits at the far end of the range from the canvas.

  One guessing defect went with it: the diff-root hue scan now ignores candidates that cannot be read on the canvas. An unreadable guess is no better than the polarity hue, and forcing AA onto it moved the color far further than falling back.

  Converted themes from the config `themes/` directory run the same sweep as the bundled ships; `enforceAa: false` stays a test-only escape hatch.

- 5935549: **Generated pigment themes declare their `appearance`** (`"light"` or `"dark"`), taken verbatim from the Shiki source theme's polarity instead of leaving pi to infer it from the colors. `isLightTheme` (HTML-export CSS) and the terminal-default color guesses now read a declared fact rather than `detectAppearance`'s luminance guess, which can come out backwards on low-contrast palettes. The `light/dark` half of a pair is still selected by terminal appearance, not by the candidate theme. A converted theme file carries its polarity the same way — VS Code JSON has `type` — so only the traditional TextMate shape has nothing to read: a `.tmTheme` or a `settings`-only JSON goes on inferring `appearance` from the background's luminance.

  Generated files point `$schema` at pi's canonical published schema, `https://pi.dev/schemas/theme.schema.json`; the old `raw.githubusercontent.com` path 404s, so hand-edited copies had no editor validation or completion.

  Note: pi's `/settings` theme picker is upstream and lists every theme flat; an extension cannot filter it by polarity. `appearance` is the data a future upstream grouping would need.

- 20434a3: **Generated themes prefer the author's own declarations over derived guesses, across every color family they touch.** Where a theme declares them, conversion now takes `editorError.foreground` / `editorWarning.foreground` (48 and 47 ignored declarations across the bundled themes) with the polarity hue as the fallback and the error box tint following the chosen color — Dracula's warning is cyan by its own declaration, faithful to the source rather than a bug. A declared `editor.selectionBackground` / `editor.findMatchBackground` is used even when it carries alpha, its RGB composited onto the canvas rather than dropped for a computed tint (41 selection and 31 find declarations were ignored before).

  Bundled themes go through the same diff-roots path user theme files already did, so a declared `diffEditor.insertedTextBackground` / `removedTextBackground` reaches the registered `toolDiff*` slots; failing that, a `markup.inserted` / `markup.deleted` foreground is the diff root — the author's diff-content color instead of a hue guess over every token. A declared `textLink.foreground` is the accent, with the most-saturated-token scan as the fallback: nord, One Dark and GitHub Light previously took their red. The diff tint is the one projection that drops alpha rather than compositing it, keeping its RGB, and it applies only where the theme declares no explicit diff text.

  `success` is the one slot with no declaration to prefer: a theme's `editorInfo.foreground` is an info hue, not a success green.

## 0.4.2

### Patch Changes

- 72116fd: Show a pending-call heartbeat on tool headers. Every call header now trails a muted braille spinner cell in the settled `· ✓` status slot while the execution is live, so a quiet pending period (a slow read, a bash command with no output yet) reads as "working", not "frozen". The cell trails so the `$` keeps column 0 and the body's left edge never moves, and the re-armed placeholder reuses the last committed width so the middle-cut never shifts between frames.

  The frame is a pure function of the wall clock (one glyph per 250ms bucket), never a per-render counter: a counter would change the header key every frame, and the preview task's own commit re-runs `renderCall` — a self-driving repaint loop disguised as the feature. A ~4Hz interval re-invalidates the row while pending (quiet periods raise no tool events), swept on every final frame; a resumed row never arms one.

  It proves the render loop is alive, never that the model streams: a provider stall with an idling TUI keeps spinning (see the heartbeat exception in ADR 0005).

- 0645eff: Trim per-frame work the renderers repeated on every frame for a stable result: read memoizes the masked text's line split alongside the masked text (one split per result instead of one per frame), drops the per-frame `entries` filter nobody read (`outputTaskKey` only needs output length + hash), and keys the read memo on path:offset:limit since the limit shapes the notice lift. Grep folds its empty-output verdict into the shared derivation instead of allocating a trimmed copy per frame, and find moves its glob-anchor/emphasis computation into the styled closure so it runs only on frames that actually re-render.
- f50d511: The write details channel no longer stashes a second copy of a write's content and display path at `tool_call`; it reads both from the paired `tool_result` event's arguments. That event carries the validated args the tool actually received, so an extension that mutates them in place (pi documents `tool_call` `event.input` as mutable) now renders the true old→new diff — previously the stale snapshot made the self-check drop the preview. The self-check is otherwise unchanged: a sibling write or an aborted call still yields no diff rather than a wrong one.

## 0.4.1

### Patch Changes

- 165efc1: Fix rendering falling back to pi's plain output in sessions that spawn an in-process subagent (e.g. `@gotgenes/pi-subagents`). The SDK caches the extension factory per working directory, so a child session reuses the parent's module instance and fires `session_start`/`session_shutdown` again; the render kit lived in module state, so the child overwrote or cleared the parent's. The parent, which never re-fires `session_start`, then decorated with the child's `cwd`/config (the write channel's self-check dropped every diff) or stopped decorating at all: no syntax colors, no diff preview, no header ellipsis. The kit and the write stashes now live in the extension instance's closure.

## 0.4.0

### Minor Changes

- 7782b9d: pi-pigment no longer registers any tool: it contributes a single `registerToolRenderer` resolver for the eight built-in names (`write`, `edit`, `bash`, `powershell`, `grep`, `ls`, `find`, `read`), so execution, the model-facing result, and name ownership stay pi's own. This ends the same-name registration that silently shadowed a later extension's tool, and drops the shell-settings rebuild (`commandPrefix`/`shellPath` flow through pi's own bash tool untouched). The write diff — which the SDK's write tool does not carry — is captured through the `tool_call`/`tool_result` hooks and emitted only when the file that landed byte-equals the supplied content.

  Breaking for consumers:

  - The public `pi-pigment/render-kit` entry (import module and `globalThis` publication) is removed; it existed only because pi lacked a renderer-only override.
  - Requires `@earendil-works/pi-coding-agent` and `@earendil-works/pi-tui` >= 1.0.1 < 2.0.0 (previously >= 0.85.0) — `registerToolRenderer` landed in 1.0.1.
  - Replayed rows may now show a `Took` footer on pi 1.1.0+ (pi's recorded execution time; the render-state clock remains the fallback on 1.0.1, HTML export, and partial frames).

## 0.2.0

### Minor Changes

- b71229c: Third-party extensions can now borrow pi-pigment's rendering instead of racing it for the tool name: `pi-pigment/render-kit` installs the renderers on YOUR tool definitions (`decorate`) and leaves your `execute` untouched, and a zero-dependency publication channel (`globalThis[Symbol.for("pi-pigment.render-kit.v1")]`) serves extensions that must not import the package. Borrowed rendering is contract-tested byte-identical to pi-pigment's own wrappers. See `docs/integrating.md`.

### Patch Changes

- 9eb6889: The styled-text cell walk no longer allocates a record per cell: `forEachCell` visits a cell's span, column count and escape flag as primitives (its generator predecessor yielded one object per cell and measured 3–8x an inlined walk, the allocation being the bulk of it), and each call site slices the cell's text only when it needs it. Measured on the frame paths, per pair of interleaved runs against the previous code: styled-line width measurement ~5x faster, CJK ~2.5x, styled truncation ~2.5x, background injection with emphasis ranges ~1.4x; the plain-ASCII fast paths are untouched.
- 9eb6889: Rows that carry grapheme clusters (combining marks, ZWJ emoji, flags, conjoining jamo, …) are now walked and measured by cluster, using pi-tui's own `visibleWidth`, so widths, wrapping, truncation and word-emphasis highlights match what the renderer draws; lines without cluster-forming code points keep the fast per-code-point path. The gate's code-point tail is derived from the runtime's `Intl.Segmenter` instead of a hand-copied chart — `pnpm run check:risky-tail` re-derives it — and now covers the Hangul jamo Extended-A/B blocks and the Kirat Rai joiners the previous ranges missed.
- b71229c: Session render state is now a per-session value (`RenderSession`) instead of module-level singletons: diff roots, the theme selection, the user-theme environment, and the converted-theme map are resolved once at `session_start` and carried by the session — the four `set*` writes and the ambient reads they fed are gone, and two sessions in one process can no longer leak theme state into each other.

  Pinning that seam surfaced a real rendering bug, fixed here: Shiki keys its theme registry by name, and a created grammar's color map ignores a later same-name `loadTheme` — so two user theme files sharing a stem (a re-edited file, two projects in one process) rendered with the FIRST file's colors while reporting the new ones. File-channel themes now register under a content-distinct name (`stem~fingerprint`), matching the highlight cache's existing key. Bundled, enforced, and patched theme variants were never affected.

- 722c4a8: Tool wrappers now yield to names another extension (or an SDK-passed custom tool) already claimed: before registering, the extension reads pi's merged tool registry and skips any of the seven built-in names whose source is not `builtin`, with a one-line notice per session. A resume/fork re-fire does not yield to the extension's own prior registration. Names claimed after pi-pigment's `session_start` fires keep pi-pigment's wrapper live under pi's load-order merge (the late registration is dropped with a conflict log); factory-time registration, the render kit, or `disabledTools` cover that case. See ADR 0005's addendum and `docs/integrating.md`.

## 0.1.4

### Patch Changes

- ef064a5: Fix the bash wrapper silently dropping pi's shell settings. Registering the pigment bash tool under the same name replaces pi's builtin definition wholesale, execute included, so the wrapper now reads the same `SettingsManager` pi itself uses and passes `commandPrefix`/`shellPath` into `createBashToolDefinition` — a configured shell or command prefix runs again. - 98d4177: Internal restructuring, no behavior change: the pi extension entry moves out of `src/` to `index.ts` beside it, matching the other extensions in this repo. package.json `exports` and `pi.extensions` point at `./index.ts`, so loading and importing are unchanged.
- 680e42d: Stop persisting the execution timing: the `Took` footers (grep/find/ls, and the error frame) now read the clock pi's shell renderer already keeps in the render state — armed by `renderCall` while the execution is live, fixed by the first settled `renderResult`. This also removes the one field pi-pigment appended to every tool result (`pigmentElapsedMs`) plus the two bounded maps that backed the thrown-error path.
