# 0005 — Jev reviewer via the ReviewerEngine seam

- Status: accepted (2026-09-20)
- Context: TypeSafe's Jev (System One) returns calibrated-probability answers to typed questions instead of generated text, so it cannot hang behind the `ModelRegistry.complete` text-generation seam. The correct cut point is the `ReviewOutcome` producer.
- Decision: introduce a `ReviewerEngine` seam (`review(ctx) -> EngineReviewResult | EngineMachineryFailure`). `createLlmEngine` (factory, no class) carries the existing find/auth/prompt/reviewModel path; `createJevEngine` calls the official `@typesafe-ai/sdk` (`systemOne`) with four ported questions (`danger_category`, `intent_match`, `unconditionally_safe`, `risk`) and synthesizes a verdict (`synthesizeJevVerdict`). Config: `provider: string | { type: "typesafe", baseUrl?, apiKey? }`, top-level `model` unchanged, thresholds in a `typesafe` section; `reasoning`/`maxTokens` ignored in Jev mode; `instructions` overlays (string = shared background, object = per-question additions) instead of replacing.
- Consequences: Jev answers never produce free text, so deny reasons are synthesized from the danger-category name with a generic fallback; low confidence defers (the Jev analogue of the LLM lean). `modelId` records `typesafe/<model>`. `typesafe.timeoutMs` sets the SDK per-attempt timeout (timeouts fail outright — only 408/429/5xx retry); top-level `timeoutMs` is the fallback.
