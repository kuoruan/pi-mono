# 0005 — Jev reviewer via the ReviewerEngine seam

- Status: accepted (2026-09-20)
- Context: TypeSafe's Jev (System One) returns calibrated-probability answers to typed questions instead of generated text, so it cannot hang behind the `ModelRegistry.complete` text-generation seam. The correct cut point is the `ReviewOutcome` producer.
- Decision: introduce a `ReviewerEngine` seam (`review(ctx) -> EngineReviewResult | EngineMachineryFailure`). `createLlmEngine` (factory, no class) carries the existing find/auth/prompt/reviewModel path; `createJevEngine` calls the official `@typesafe-ai/sdk` (`systemOne`) with ported questions (`danger_category`, `intent_match`, `risk`) and synthesizes a verdict (`synthesizeJevVerdict`). Config: `provider: string | { type: "typesafe", baseUrl?, apiKey? }`, top-level `model` unchanged, thresholds in a `typesafe` section; `reasoning`/`maxTokens` ignored in Jev mode; `instructions` overlays (string = shared background, object = per-question additions) instead of replacing.
- Consequences: Jev answers never produce free text, so deny reasons are synthesized from the danger-category name with a generic fallback; low confidence defers (the Jev analogue of the LLM lean). `modelId` records `typesafe/<model>`. `typesafe.timeoutMs` sets the SDK per-attempt timeout (timeouts fail outright — only 408/429/5xx retry); top-level `timeoutMs` is the fallback.
- Update (2026-09-28): the seam still holds, but the two factories were superseded by one pooled supervisor (`createReviewerPool`) walking a mixed endpoint list (primary + ordered `fallbacks`) through per-lane `LaneAdapter`s — `createLlmAdapter`/`createJevAdapter`, assembled by `buildReviewerPool`. Failover between lanes is now uniform (see the mixed-lane changeset).
- Update (2026-10-08): the lanes are now named for the capability, not the model — `chat` and `classifier` (`createChatAdapter`/`createClassifierAdapter`, `engines/chat`/`engines/classifier`, `synthesizeClassifierVerdict`); only the ported three-question protocol and the real model ids (`jev-1.13`, `jev-latest`) keep the Jev name. The classifier lane gained a second backend: a registry entry (`modelType: "classifier"`) runs through Pi's `modelRegistry.classify`, translated to and from the SDK's shapes in `engines/classifier/registry-client.ts`. Three config-surface changes ride along: the threshold section is `classifier`, with `typesafe` folded into it per layer as a deprecated alias — a project's old key still beats the global layer's new one, and only one file writing both keys is rejected; the block carries no transport knob (the primary timeout is the top-level `timeoutMs` for both lanes) and a `timeoutMs` left inside either block keeps parsing but is ignored and reported; and `instructions` became lane-uniform (a string broadcasts an append to both lanes, an object carries per-lane `chat`/`classifier` slots, and only the `chat` slot can `replace`, since the classifier's built-in reviewer background, questions and criteria are the answer contract its thresholds are calibrated against).
